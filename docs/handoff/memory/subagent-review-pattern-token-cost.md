2026-09-22 下午跑階段 5 更版機制＋租戶收尾，使用者問「為什麼突然 token 大爆噴」。實測：**週額度 60% → 83%，一個下午 23 個百分點**，五小時額度到 79%。總計 **19 支 subagent、約 310 萬 token**。

最貴的幾支（單支 subagent_tokens）：舊版退役 304k、更版頁 253k、整枝審查的修正 216k、整枝審查 207k、階段 3 調查 198k、cron 191k、拆合併與重啟 187k。**調查類（研究現況、不寫碼）也要 170–200k**，跟實作關同級。

**Why:** 三個因素疊加——①每一關都派審查，等於每件事兩份；②使用者說「能開 sub 就先開」之後幾乎沒讓它閒過，同時 2–3 支；③改規則前每支都跑兩次全套（基線＋完成），agent 要讀輸出算差額。派工說明寫得長（1500–3000 字）也是成本，但相對 agent 自己的執行量是小頭。

**不是白花**：當天審查抓到兩個 Critical（維護旗標會卡住整小時、標記已發布卻沒真的重啟成功）與控制者自己寫進註解的一段假歷史。整枝審查則是第五次抓到「不屬於任何一關的需求」。

**How to apply:** 要省時照這個順序砍——①機械性工作（改文案、搬位置、加 v-if）不派審查，併進最後的整枝審查，約省三成；②調查類用小模型（那幾支 200k 不需要最強的）；③一次只跑一支，慢一半但額度平滑。**整枝審查不要砍**——它的命中率是這套流程裡最高的。額度緊時先看 `seven_day.utilization` 再決定當天開幾支，見 [[limit-parallel-subagents]]。
