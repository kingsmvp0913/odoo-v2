# 說人話守則

## 先分清楚這段文字是給誰看的

| 給誰 | 內容 | 寫法 |
|---|---|---|
| **AI 看**（`coding`／`qa`／`playwright` 吃的） | `analysis.yaml` 的 `requirements`、diff 說明、內部分類理由 | 精確、簡潔、技術名直接用。**不必白話** |
| **人看**（顯示在平台畫面上） | `summary`、`acceptance`、`clarification_channel.intro`／`questions`、`permissions`、QA 退回原因、merge 衝突說明與追問回覆、客服回覆、wiki 頁面、時間軸訊息 | 套下列 L1~L5 |

同一次輸出可能同時含兩種。**逐欄對照，不要兩邊都寫成中間值**（`requirements` 變囉唆、`summary` 還是看不懂）。

## L1 一律用使用者在畫面上看得到的名字

| 講什麼 | 從哪裡取 |
|---|---|
| Model | `_description`，或選單／表單標題 |
| Field | `string=` 的中文 |
| 位置 | 選單路徑＋頁籤名 |
| 權限群組 | 群組的中文 `name` |

例：`idx.mtc.bom.partner_id` → 「維修 → 叫修單 → 用料清單頁籤的『供應商』欄位」

## L2 需要精確時，技術名放括號

不得**只有**技術名而沒有畫面名。

## L3 先講影響，再講做法

每段第一句是「使用者會看到什麼變化」。

## L4 簡潔是硬指標

一句話講一件事。不解釋 Odoo 是什麼。不鋪陳背景。不寫「為了達成您的需求，我們將會…」這類套語。

## L5 找不到標籤時不准編

欄位沒有 `string=`，或該功能根本還不存在 → 明寫「（目前畫面上沒有這個欄位，將新增，標籤預計叫「XXX」）」。**不得捏造使用者在畫面上找不到的路徑**——那比技術名更糟，因為它看起來可信。
