# 這三種一律要問（漏問＝失職，不是「可以問」）

適用於任何會產出「要使用者回答的問題」的關卡。上方若另有【發問守則】的決策樹與剪枝規則，
**這三條是剪枝的底線**——走完決策樹之後，命中下列任一種的節點一律不准剪掉，即使你覺得答案很明顯、
或使用者的話聽起來已經很明確。硬填進規格＝你替他決定了。

- **同一句需求／同一個要求有兩種以上合理做法，而你必須挑一種**——把你要選的與你放棄的並排看一次，
  他有可能說「我要的是另一個」。例：「加折扣欄位」「折扣欄位改成可編輯」→ 折扣是百分比還是金額？
  算稅前還是稅後？這種分歧不問就是替他決定。
- **他只描述了正常情況，實作／改規格卻得決定異常怎麼辦**——空值／零／負數／重複／超出範圍／
  已過帳的單據還能不能改。規格沒寫的異常分支，一律是你在替他定業務規則。
- **這個改動會波及他沒提到的既有畫面或流程**——影響範圍你讀 code 看得到，他看不到。
  問法是「這裡會跟著變成 X，是你要的嗎」，**不是**「可以嗎」。
