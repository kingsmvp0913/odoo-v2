# Odoo 原始碼查證指引

這份檔案會被複製進查證用的工作目錄，agent 在動手前先讀它。

抽成檔案而不是塞在 prompt 裡的理由：查證方法會隨實測慢慢調整，而 prompt 每次
呼叫都要重傳一遍。放檔案則是「要用才讀」，而且改這裡不必動程式碼。

> 為什麼不做成 Claude Code 的 skill：查證子行程的工作目錄是暫存目錄，
> 專案的 `.claude/skills/` 在那裡**載不到**（實測確認：只載得到 `~/.claude/skills/`
> 的 user scope）。而 user scope 不進版控、又是全平台共用，等於破壞這支刻意
> 做出來的隔離。放進沙箱目錄才同時滿足「進版控」與「只有這個 agent 看得到」。

## 可以查的範圍

**只有 `src/` 底下**。那是這個 Odoo 版本的原始碼。

不要讀 `src/` 以外的任何路徑，也不要往上跳目錄。跳出去的東西與題目無關，
而且回報上來會被 Node 端直接丟棄（那一關是硬的，不是叮嚀）。

## 先認題型，再決定要不要查

| 題型 | 怎麼查 |
| --- | --- |
| **機制題** — 欄位定義在哪個 model、預設排序、演算法、domain 限制、狀態流轉 | Grep `src/`。這是本機原始碼，精準而且版本正確 |
| **操作題** — 某設定在哪個選單、按鈕在哪一頁、功能概念敘述 | 原始碼要先猜對檔名才找得到，通常查不到。查不到就說查不到 |
| **情境推算題** — 看圖、算價、算日期、算數量 | 原始碼不回答「這張圖像什麼」，一律回查不到 |

## 同一批題目通常屬於同一個模組

一次收到的題目來自考卷的同一頁，而同一頁幾乎都在問同一個 Odoo 模組
（Project 那頁全是 `project/`、eCommerce 那頁全是 `website_sale/`）。

所以**先把那個模組的目錄結構摸清楚一次**，後面每一題都能重用，不要每題
從頭 `Grep` 整個 `src/`。

先跑一次 `Grep` 或 `ls` 認出模組根目錄，再往 `models/`、`views/`、
`wizard/`、`report/` 裡面找。

## 最重要的一條

**查不到就說查不到，不要硬湊。**

拿無關的片段替推理背書比不查更糟——那會讓一個純粹靠猜的結論看起來有證據
支撐，而下游會照著這個假象給它高信心。

`found` 設 false、`evidence` 給空陣列、`reason` 寫清楚為什麼查不到。

## 證據的形狀

- `ref` 一律是 `src/…:行號`，指到**關鍵那幾行**，不是整個函式。
- `excerpt` 只貼關鍵幾行。太長會被截斷。
- `supports` 填這些證據指向哪個選項字母。指向候選答案以外的選項時就填那個，
  不要為了迎合候選答案而改。
